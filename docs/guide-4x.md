# 第 3 步：把 3.9 的数据迁进 4.x

> 面向已经走完 2.0 → 3.9 的人：用 4.x **官方内置**的「加载历史聊天记录」，把 3.9 账号目录里的聊天与附件吃进 4.x。**这一步没有迁移脚本，主要是界面操作加结构对账。**

## 目标

* 把 3.9 客户端目录里的历史聊天记录（文字、图片、语音、视频、文件、卡片）导入 4.x。
* 导入由**客户端自己完成**：我们只负责触发、等待、以及**结构性验收**。
* 导入是**增量合并**：4.x 里已经存在的月份，会与本机旧目录里的对应内容**相加**，不覆盖、不重复。
* 大二进制走 NTFS **硬链接**落地：磁盘上通常只有一份字节、两个路径。

> 这一段的正确性由**结构对账**保证（月份指纹、inode 命中、逐月文件数），而不是靠人肉点开每一条消息。

## 前提

| 项 | 要求 |
|---|---|
| 3.9 侧已就绪 | 2.0 → 3.9 的迁移已完成，且能在 3.9 客户端里正常打开、浏览 |
| 目录布局 | 4.x 账号根 `xwechat_files\<账号>_<短hash>\` 与 3.9 的 `WeChat Files\` **并列**在同一个父目录下（官方迁移期望两者是兄弟目录） |
| 源客户端 | 迁移开始前，把 **3.9 客户端干净退出** |
| 目标客户端 | 4.x 已登录；迁移的**触发点是登录**，按「首次以该版本登录」的时机操作 |
| 磁盘空间 | 目标盘余量足够（客户端会提示「导入最多需要 `<N>` 空间」） |
| 目录位置 | 旧目录**不要**落在云盘同步范围内，否则会被拦下 |
| 备份 | 迁移**不会删除源数据**，但仍建议先给 3.9 数据根留一份只读快照 |

## 步骤

### 1. 备份并记录迁移前基线

* **做什么**：给 3.9 数据根留快照，并记下 4.x 迁移前的状态，供后面的「相加检验」使用。
* **怎么做**：

  ```powershell
  # 3.9 侧：按月份记录文件类附件的文件数
  Get-ChildItem -LiteralPath '<3.9>\FileStorage\File' -Directory |
    ForEach-Object { '{0}`t{1}' -f $_.Name, (Get-ChildItem -LiteralPath $_.FullName -Recurse -File).Count }
  ```

  同样记下 4.x 的 `msg\migrate\File\<年-月>\` 月份集合与文件数。

* **验收**：得到两份基线表（旧树、4.x 迁移前）；旧树里 `nlink > 1` 的文件也一并记下 inode，便于后面比对。

### 2. 干净退出 3.9 客户端

* **做什么**：确保源客户端不再占用旧目录。
* **怎么做**：菜单正常退出 3.9，确认进程消失。
* **验收**：任务管理器里不再有 3.9 的进程。**不要直接杀进程后立刻动手**。

### 3. 首次登录 4.x，在弹窗里选「加载」

* **做什么**：这是官方迁移的**触发点**。
* **怎么做**：升级/首次登录后会弹**「版本更新」**对话框，标题句是 **`加载版本更新前的聊天记录`**，
  按钮为 **`加载` / `不加载` / `暂不处理`**。选 **`加载`**。
* **验收**：开始出现迁移/导入进度提示。

> * 选 **`暂不处理`**：**下次登录仍可再选**，不会丢机会。
> * 选 **`不加载`**：会提示「后续将无法加载之前版本的聊天记录」——一旦拒绝并清掉旧目录，就没有第二次。

### 4. 之后也可以从主窗口的 `≡` 菜单再次进入

* **做什么**：错过登录弹窗时的手工入口。
* **怎么做**：主窗口左侧图标栏**最底部**有一个 **`≡`**（三条横线）。点开后的菜单依次是：
  `聊天文件` / `聊天记录管理` / **`加载历史聊天记录`** / `锁定` / `意见反馈` / `设置`。
* **验收**：出现与第 3 步相同的加载界面。

> ⚠️ 图标栏**底部**这一组（手机、`≡`）很容易被忽略 —— 只扫上半部分会以为「没有设置入口」。
>
> **不要混淆的三个流程**（UI 文案相近，做的事完全不同）：
>
> | 菜单项 | 做什么 |
> |---|---|
> | **加载历史聊天记录** | ★ 从**本机旧版微信目录**导入（本文的主角） |
> | 从手机导入聊天记录 | 通过手机端把记录传到电脑（网络传输，与旧目录无关） |
> | 迁移文件到新的存储位置 | 把 **4.x 自己**的数据根挪到别的盘（与旧版无关） |

### 5. 授权旧微信目录

* **做什么**：让客户端能读旧目录。
* **怎么做**：出现 **`授权访问原微信目录以导入聊天记录`** 时，授权的目录是
  **`...\Documents\WeChat Files`（上一层）**。
* **验收**：授权后开始真正导入。

> **不是** `WeChat Files` 里面的账号子目录 —— 选错一层会认不到数据。

### 6. 等待迁移完成

* **做什么**：让官方流程跑完。
* **怎么做**：客户端文案写明 **`导入过程中你可以正常使用微信`**，所以可以照常用，但**中途别退**。
* **验收**：导入结束、进度消失；旧目录里**源数据仍在**（迁移不删源）。

> **别踩**：`退出微信会停止迁移` / `退出登录会停止迁移` / `重启微信会停止迁移`。
> 看到 **`已暂停加载聊天记录`** 时，那是**可恢复的暂停，不是失败**。

### 7. 逐月对账（迁移后立即做）

* **做什么**：用迁移前不存在的东西做**指纹**，证明数据真的进来了。
* **怎么做**：对照第 1 步的基线，逐项核对。
* **验收**（判据见下一节清单）：新增月份=旧目录里有而 4.x 原先没有的月份；两边都有的月份满足
  `4.x迁移后 = 4.x迁移前 + 3.9`；旧树 `nlink > 1` 的 inode 在 4.x 里 **100% 命中**；
  两侧的 `<会话>\<媒体子目录>\<月份>` 组合差集为 0；统计 `(数字)` 后缀文件的 mtime，
  **不应出现迁移当天的时间**；旧树 `sha256` 与文件数不变。

### 8. 浏览抽样验收

* **做什么**：打开几个会话翻一翻，确认能看、能播、能打开。
* **怎么做**：逐个点开文字、图片、语音、卡片、文件；视频按抽样看。
* **验收**：图片、语音、卡片、文件正常；视频未发现异常（视频属抽样，非逐条）。

> **表情转圈是正常的**：4.x 渲染 `Type=47` 表情时走的是缓存
> `cache\<年-月>\Emoticon\<前2位>\<32hex>`，**打开会话、等一会儿**客户端会自己取回；
> **不需要逐条转发**（转发的唯一作用是**加速**），**合并转发**也不会触发逐条渲染。
> 新表情通常秒开，十年前的表情可能几秒到一分钟 —— **转圈 ≠ 迁移坏账**。

## 4.x 数据落位

| 路径（相对 4.x 账号根） | 放什么 |
|---|---|
| `msg\attach\<会话md5>\<年-月>\Img\<id>[_t\|_h\|_W].dat` | 图片（原图 / 缩略图 / 高清）；`<会话md5>` = `md5(StrTalker)` |
| `msg\attach\<会话md5>\<年-月>\Rec\<16hex>\{Img,F,V}\...` | 「聊天文件」视图自己的副本目录 |
| `msg\file\<年-月>\<名字>` | 文件类附件；名字可能是原始文件名，也可能是 `<内容md5>.<ext>` |
| `msg\video\<年-月>\<id>.mp4`（+ 同名 `.jpg` 封面） | 视频 |
| `msg\migrate\{File,Video}\<年-月>\<名字>` | **迁移暂存区**；4.x 真正读的是 `msg\file` / `msg\video` |
| `cache\<年-月>\Emoticon\<前2位>\<32hex>` | 表情渲染缓存 |
| `business\emoticon\{Persist,PersistStore,Thumb,ThumbStore}\...` | 表情库（索引驱动） |

要点：

* 4.x 的图片名是 **`<内容md5>_W.dat`** 这种带哈希的形态，3.9 侧是**数字名**
  ⇒ **不能按文件名比对两侧**，只能用内容或 inode。
* **`<会话md5>` 两侧是同一个值**，这是最好用的锚点。
* 迁移**基本不搬表情**：旧版表情要靠第 8 步的缓存取回机制，不是靠迁移。

## 对应脚本

| 环节 | 脚本 | 命令 / 参数 | 备注 |
|---|---|---|---|
| **官方迁移本身** | — | — | **没有脚本，只能手工界面操作**（第 3–6 步） |
| 备份与迁移前基线 | — | — | **没有脚本，手工/自带 PowerShell** |
| 逐月对账、inode 命中 | — | — | **没有脚本，手工统计** |
| 浏览抽样验收 | — | — | **没有脚本，只能人眼** |
| 用已有密钥解开单个 4.x 库 | `wx4_decrypt.py` | `wx4_decrypt.py <库路径> --keys <密钥文件> [--check] [-o <输出>]` | `--check` 只校验 page-1 HMAC；`--keys` 格式见脚本 docstring |
| 磁盘附件清单（双哈希） | `wx4_attach_inventory.py` | `--root <数据根> --out <TSV> [--threads N] [--limit N]` | 只读 |
| 从库里抽附件引用集 | `wx4_attach_refs.py` | `--root <数据根> --out refs.json.gz --keys <密钥文件> [--work DIR] [--no-cache]` | 只读 |
| 重复 / 孤立审计报告 | `wx4_attach_audit.py` | `--inv <TSV> --refs <refs.json.gz> --out <前缀>` | 需要上面两步的产物 |
| 硬链接折叠 | `wx4_attach_dedup.py` | `plan` / `apply` / `verify` / `rollback`（见脚本 docstring） | **默认 dry-run**，`--yes` 才真做 |

> **必须说清楚**：**迁移这一段没有任何脚本**。上表里除了 `wx4_decrypt.py` 与那四个附件工具，
> 其余环节都只能手工点、手工记、手工比对。附件工具属于**迁移之后**的精简与审计，见
> [guide-attachments.md](guide-attachments.md)。
>
> 4.x 的库是 SQLCipher 4：AES-256-CBC / page 4096 / reserve 80 / HMAC-SHA512 / raw key（不经 PBKDF2），
> 且**每个 `.db` 各有一把独立密钥**。`wx4_decrypt.py` 的输入是**你自己已有的密钥文件**
> （`--keys <文件>`，格式见脚本 docstring），本指南不涉及密钥来源。

## 验收清单

* [ ] 迁移前基线已留档（3.9 逐月文件数、4.x 迁移前逐月文件数）。
* [ ] **月份指纹**：迁移后 4.x 新增的月份 = 旧目录里有、4.x 原先没有的那些月份。
* [ ] **相加检验**：两边都有的月份，`迁移后 = 迁移前 + 3.9`。
* [ ] **inode 命中率**：旧树 `nlink > 1` 的文件 inode 在 4.x 中 **100% 命中**。
* [ ] **会话 × 月份覆盖**：两侧 `<会话>\<媒体子目录>\<月份>` 组合集合，差集为 0。
* [ ] **零重复**：`(数字)` 后缀文件的 mtime **没有**迁移当天的时间戳。
* [ ] **源未变**：旧树 `sha256` 与文件数迁移前后一致（只多出无害的 `-shm` / `-wal` 边车文件）。
* [ ] 抽样浏览：图片 / 语音 / 卡片 / 文件正常；视频抽样未见异常。
* [ ] 迁移全程没有退出微信、退出登录或重启。

## 常见失败

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 登录时没有弹「加载」对话框，`≡` 菜单里也没有该项 | 之前选过「不加载」并清掉了旧目录记录；或旧目录未被识别 | 确认旧目录仍在、且与 4.x 账号根并列；重新登录再选一次「加载」 |
| `原微信客户端没有当前账号的聊天记录` | 授权/识别的目录层级不对，或旧目录里没有当前账号 | 授权 `...\Documents\WeChat Files` **这一层**，不要选里面的账号子目录 |
| `当前磁盘空间不足` / `导入最多需要 <N> 空间` | 目标盘余量不够 | 腾出空间后重试；期间别清理旧目录 |
| `已暂停加载聊天记录` | 可恢复的暂停（例如被系统挂起） | 这是**暂停不是失败**；保持微信在前台、别退出登录，等它继续 |
| `由于部分文件无读写权限` → `未能加载之前版本的聊天记录` | 旧目录权限不足 | 按提示「重启电脑后再试」，或先把旧目录权限放开 |
| `由于部分文件已损坏` → `未能加载部分聊天记录` | 部分是部分，不是全败 | 按第 7 步逐月对账，缺哪个月补哪个月；已导入的仍保留在客户端里 |
| 迁移后部分表情一直转圈 | `Type=47` 表情走缓存，需要联网取回 | 打开对应会话**等一会儿**，不要逐条转发、也不要重装客户端 |

> **两条容易被误判的事**：
> ① 旧目录里出现同名的 `(数字)` 后缀文件（如 `xxx(1).pdf`）**是原文件名的组成部分**，
> 不能据此判断「迁移产生了重复」；
> ② 迁移后 4.x 目录**没有明显变大**是**正常现象** —— 大二进制走的是硬链接，磁盘上只有一份字节。
